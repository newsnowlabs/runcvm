# virtiofsd patches

RunCVM builds Alpine's own `virtiofsd` package (`community/virtiofsd` in aports, at the version Alpine ships) with these patches, applied in filename order (see the `alpine-virtiofsd` stage in the `Dockerfile`). Each is a `git format-patch` file, one change each, against that version.

| Patch | Origin | Effect | Drop when |
|---|---|---|---|
| `0001-passthrough-Let-the-guest-cache-symbolic-link-target.patch` | RunCVM; to be proposed upstream | Negotiates `FUSE_CACHE_SYMLINKS` unless `--cache=never`: the guest keeps symbolic link targets cached instead of asking for each on every path walk (e.g. one request fewer for each run of a BusyBox applet) | A `virtiofsd` release has it |
| `0002-passthrough-Set-FOPEN_NOFLUSH-on-files-opened-read-o.patch` | RunCVM; to be proposed upstream | Sets `FOPEN_NOFLUSH` on files opened read-only: the guest skips a flush request, which has no effect there, on every `close()` | A `virtiofsd` release has it |
| `0003-passthrough-drop-CAP_FSETID-in-fallocate-and-copy_fi.patch` | Backport of upstream commit `fc18227` (not in 1.13.3) | With `--killpriv-v2`, clears setuid and setgid bits, and file capabilities, on `fallocate` and `copy_file_range` | A `virtiofsd` release that Alpine ships has it |
| `0004-passthrough-Let-the-guest-decide-on-setuid-setgid-in.patch` | RunCVM; to be proposed upstream; needs 0003 | With `--killpriv-v2`, declines `copy_file_range` to a file with a setuid or setgid bit, so that the guest copies with ordinary writes and keeps or clears the bits as on a local file system | A `virtiofsd` release has it, or 0003 is dropped |
| `0005-passthrough-Have-the-guest-refetch-setuid-setgid-fil.patch` | RunCVM; to be proposed upstream | With `--killpriv-v2`, gives the attributes of regular files with a setuid or setgid bit a timeout of zero, so that the guest never applies, or shows, bits that `virtiofsd` has cleared (without it, with writeback caching, a user able to write to a setuid-root file could run it as root after modifying it) | A `virtiofsd` release has it |
| `0006-passthrough-Optionally-let-the-guest-cache-names-th.patch` | RunCVM; to be proposed upstream | Adds `--negative-timeout=SECONDS` (default 0, off): with `--cache=auto` or `always`, a lookup of a name that does not exist is answered with a negative entry the guest may cache for that long (capped at the policy's entry timeout), rather than with `ENOENT`, which it does not cache. RunCVM passes it with `RUNCVM_VIRTIOFSD_NEGATIVE_TIMEOUT` (default 1) | A `virtiofsd` release has it |
| `0007-sandbox-Open-proc-self-mountinfo-close-on-exec.patch` | RunCVM; to be proposed upstream, with 0008–0012 | Opens `/proc/self/mountinfo` close-on-exec | A `virtiofsd` release has the series |
| `0008-passthrough-Factor-out-CachePolicy-timeout-and-open_.patch` | RunCVM; as 0007 | Gathers each cache policy's timeouts and open flags in `CachePolicy`, with no change in behaviour | As 0007 |
| `0009-passthrough-Keep-a-cache-policy-per-inode.patch` | RunCVM; as 0007 | Keeps a cache policy on each inode, used for its replies (and its parent directory's for a negative entry's timeout), with no change in behaviour | As 0007 |
| `0010-sandbox-Optionally-open-a-second-description-of-proc.patch` | RunCVM; as 0007 | Has the sandbox open a second, independent `/proc/self/mountinfo` when wanted, with no change in behaviour | As 0007 |
| `0011-passthrough-Add-submount-cache-and-cache-path.patch` | RunCVM; as 0007 | Adds `--submount-cache=POLICY` and `--cache-path=PATH=POLICY`: a mount within the shared directory takes the policy of the longest configured path that is its mount point or a parent of it, else `--submount-cache`, else `--cache` (see `RUNCVM_VIRTIOFSD_SUBMOUNT_CACHE`) | As 0007 |
| `0012-README-Document-cache-path-and-submount-cache.patch` | RunCVM; as 0007 | Documents 0011's options in `virtiofsd`'s README | As 0007 |

Each of 0001–0006 applies, builds and passes `virtiofsd`'s tests without the others, except 0004, which needs 0003. With `--killpriv-v2`, 0003 and 0005 are needed for safety (without 0003, an unprivileged `fallocate` or `copy_file_range` keeps the bits; without 0005, the guest can keep bits that have been cleared), and 0004 for setuid and setgid semantics close to a local file system's. 0007–0012 form one series, applied in order after 0001–0006 (0009 gives a negative entry from 0006 its parent directory's policy). To drop a patch, delete its file; if a later patch then applies with offsets or fuzz, or leaves a warning, refresh it.
